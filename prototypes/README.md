Their unrelated design evidence remains useful. ## Decisions so far

Later tickets changed some of these. The ticket behind each change is in parentheses.

- Statements end with a semicolon. Semicolons are required.
- `import std::log;` imports an exported name; `::` separates path segments. Single/group imports, item/module `as` aliases, and `export import` re-exports preserve canonical type/family identity. Export functions/types directly on their declarations; ordinary declarations/import bindings are private by default. No bottom export lists, export-from form, wildcards, defaults, or string-path imports. (#17)
- Each source file defines a module. Application paths start at the entry directory; self/super paths stay within that origin root. `std` has an isolated toolchain root, used by its own unprefixed imports too. No inline modules, automatic index/mod fallback, or configurable package/search paths in v0. Load the entry/prelude/transitive import graph once, not unrelated files. Declaration cycles can work; unresolved aliases/impossible layouts fail. See [ADR 0010](../docs/adr/0010-file-modules-explicit-exports-and-privacy.md) and `10-modules/main.rill`. (#17)
- Import paths are case-sensitive origin-root paths, not lookup through prior local aliases. Grouped imports select exports from their module; competing distinct module/item identities in one namespace are errors, never precedence by filesystem/import order. Imported module qualification accesses exports, not implicit child-file loading. Types/modules and values/functions have separate namespaces; importing an exported name can bind both public halves, not a private counterpart. (#17)
- A fixed prelude supplies primitive types, compiler predicates, and canonical copy/dispose declarations, not the whole std library. Other source-level cross-module names require imports. Compiler metadata and automatic cleanup do not require source-visible private type names, and local shadowing cannot replace canonical ownership mechanics. (#17)
- `List<T>` and the key/value collection `Map<K, V>` belong to `std::collection`, along with the existing list helpers shown here. Use `Map` for the type, not `Dictionary`; lowercase `map(...)` remains the transformation function. The [#23 catalogue](../docs/standard-library-contracts.md) records the confirmed owned/hash-map/explicit-mutation interfaces, u64 counts, checked queries and map callback contracts.
- Ordinary top-level execution runs only in the file you run; there is no `main` function or implicit module initializer/exported runtime let. `rill test` runs independent expectations, including imported modules once, not ordinary startup code. Parse/type-check loaded startup and expectation bodies in both modes, but ordinary executables omit expectations and their test-only code. Expectations cannot capture startup lets. (#17, #27)
- `expect <expression>;` is a top-level, test-only declaration requiring a `bool`: `true` passes and `false` fails. It is a keyword, not an imported function, and is rejected inside ordinary functions, closures, or other nested blocks. Ordinary builds neither execute expectations nor include their test-only code in the executable. Failures report the source location, expression, and useful operand values without re-evaluating expressions or changing evaluation order or short-circuiting. Production checks still use `guard`, `Result`, or `panic`. See `06-expect.rill` for the syntax and rejection examples, and prototypes 2, 3, and 5 for expectations alongside the functions they test. Those expectations construct their own inputs rather than relying on ordinary top-level startup code. (#27)
- `x |> f(y)` means `f(x, y)`. `x |> f` means `f(x)`. `x |> pad(10, _)` means `pad(10, x)`. The right side is a name, a call, or a parenthesized arrow function. `|>` binds looser than arithmetic, comparison, and logical operators, groups left to right, and unary `&` binds tighter. (#12)
- `?` after a pipe step applies to that step's result: `text |> parsePort? |> toAddress` means `toAddress(parsePort(text)?)`. (#12)
- There is no ternary. `if (c) a else b` is an expression that always needs `else`. On its own line, `if` is a TypeScript-style statement with blocks and `else if`. (#12)
- `guard <condition> else { ... }` and `guard let x = <Result> else (error) { ... }`. `(error)` binds the `Err` value. `guard` also takes a `Result` or `Option` directly, as in `guard send(&jobs, n) else { return; }`. The `else` block must leave its scope with `return`, `break`, `continue`, or a `never` call. (#11)
- Postfix `?` returns an existing `Err` or `none` early, unchanged. `inner ? outer` unwraps a successful Result or returns a new outer error caused by the complete original error; the right side is a lazy error value, not a callback. It is evaluated once only on failure, and the new wrapper records the operator's location. Infix wrapping is not defined for Option. An unused `Result` is a compile error; `let _ = x;` drops one on purpose. (#11; [ADR 0013](../docs/adr/0013-caused-by-errors-with-explicit-wrapping.md))
- No semicolon after a block, as in TypeScript.
- `let x = 1i32;` is immutable; `let mut x = 1i32;` permits reassignment and changes to owned fields. No `const` or per-field mutability declarations. Owned parameters are immutable bindings; move one into a mutable local to modify it. Loops may update mutable accumulators. (#15)
- A plain `T` parameter takes ownership, `&T` borrows read-only, and `&mut T` borrows exclusively for mutation. Callers explicitly obtain access with `&x` or `&mut x`, except for implicitly copied values such as numeric scalars and eligible records. `copy(&x)` explicitly copies; neither copying nor moving erases borrowed dependencies, and exclusive access cannot be duplicated. Enum implicit-copy eligibility follows every possible payload of the static type. `Shared<T>` gives several owners, not ordinary mutable payload access. After custom disposal, remaining initialized owned fields are cleaned up without repeating moved/disposed fields. (#7, #15, #23)
- Check borrow conflicts statically until last use, including dependencies carried in other values and uses during disposal. Recognize disjoint named-field storage locally, not arbitrary indices or disjoint pointees merely from different field names. Forwarding mutable access to a borrowing parameter reborrows it. (#15)
- `=` and compound assignments such as `+=` are statements, not expressions; no `++` or `--` in v0. `*reference` accesses the referent, while field projection through borrows remains convenient. Replacement computes the destination/RHS once, frees/disposes the old value, then installs the replacement. Cancellation delivery is deferred from old-value disposal through installation, while scheduling remains allowed; deliver pending cancellation afterward against a valid destination and clean it up once. (#15, #16)
- Reference-containing results and retained storage carry conservative input dependencies, including borrows nested in owned inputs. Check function exits against both returned values and caller-owned mutable destinations. Borrowing never extends the source's owning scope, and ordinary temporaries may be borrowed only within their enclosing statement. ADR 0011 adds direct uninterpolated-literal views with static backing, not a constant-folding or named-owner lifetime extension. See [ADR 0007](../docs/adr/0007-explicit-mutation-with-conservative-borrow-dependencies.md), `07-mutation.rill`, and `07-mutation-safety.md` for the approved design and validation cases. (#15)
- A name needs an overload declaration before it can have overloads: a body-less signature such as `function show<T>(value: &T): string;`. Bodies attach with `implement show(value: &Point): string { ... }` or `implement<T> show(items: &List<T>): string where show(T) { ... }`, not another `function` declaration. Implementations attach to the original family, including through aliases, and inherit its visibility; extending a family does not implicitly re-export the local import binding. The ordinary orphan rule permits the declaration's module or a module owning a type in the parameters; re-exporting is not defining that type. (#10, #17)
- Reject distinct ordinary implementations with identical canonical parameter patterns at collection; return types do not create ordinary overloads. #41 / ADR 0017 defines the conversion-specific source/target key, not general return-type dispatch. Repeated paths to one implementation are deduplicated. Distinct generic/specific patterns still use most-specific dispatch; incomparable matches fail at a call. Orphan placement alone does not prevent conflicts, and neither import order nor dead-code elimination selects implementations. (#17)
- Genuine guard release, counted owner/endpoint maintenance and native-borrow retention are protected canonical actions: reject user implementations that could replace them, even under nested-payload orphan permissions or without a call. Ordinary unprotected defaults remain specializable. Compiler remaining-field cleanup preserves nested obligations; #28 must validate overlap/negative-capability/cleanup state rules, not infer safety from privacy. (#17, #23)
- The most specific overload wins. `implement show(items: &List<Point>): string { ... }` beats `implement<T> show(items: &List<T>): string where show(T) { ... }`, so a generic overload is the default for types without their own overload.
- Primitive literal types and literal overloads are removed in v0; literal expressions still have ordinary base types under the established width/context rules. A known enum variant can specialize its parent enum parameter, as in `Language.French`. String-literal types/overloads may be reconsidered after v0. (#19)
- Every call resolves to one overload at compile time using static argument types. A whole-enum argument selects an applicable general implementation; variant-only implementations do not reject that fallback or synthesize a runtime dispatcher, even if they cover every variant. Missing applicable implementations and incomparable matches remain errors. Use `match` for runtime branching. (#10, #19)
- A generic overload states what it needs with `where show(T)`. Compiler requirements `callable(F, [A], R)`, `callableMut(F, [A], R)`, and `callableOnce(F, [A], R)` establish invocation/access without erasing F's capture evidence. Read-only can weaken to mutable/consuming; mutable can weaken to consuming, never conversely. (#23) `noBorrow(T)`, `sendable(T)`, and `shareable(T)` are separate compiler-recognized intrinsics, not user-implementable overloads: borrow-freedom, transfer safety, and concurrent read-sharing are distinct from copyability and invocation mode. Derive properties from known structure/captures or explicit generic requirements before monomorphization; erased arrows cannot invent environment evidence. See [ADR 0009](../docs/adr/0009-concurrency-safety-and-cooperative-cancellation.md) for the recursive rules and trusted-type exceptions. (#10, #15, #16)
- Ordinary families named in exported generic requirements must have publicly nameable exported declarations; importing an operation does not implicitly bind its requirements in source. Private value types/implementation metadata remain allowed under opacity, and compiler metadata checks are not source imports. (#17)
- v0 has no named `where` constraint groups or aliases. List each requirement explicitly on every declaration that needs it, for example `where eq(T), hash(T), copy(T), show(T)`. Grouping can be reconsidered after v0; this does not change individual overload requirements or intrinsic `noBorrow(T)`. (#20)
- If no overload is the most specific, the call is a compile error.
- `spawn(() => f(x));` runs a zero-argument, void-returning callable in the background. Import `spawn` and `stop` directly from `std`; there is no `go` keyword or `std::process` module. `spawn` returns a `Routine`. `stop(&routine)` requests cooperative cancellation and waits for termination plus cleanup; repeated/concurrent calls share termination state, self-stop panics, and freeing the handle still does not stop it. (#8, #16)
- `spawn` owns its callable and requires a borrow-free, sendable capture environment. If the caller still needs a non-copying captured value, make an explicit `copy` before creating the closure, not inside it. Scoped waiting helpers may borrow under transfer/sharing and access rules, and return valid caller-dependent borrows, never references into destroyed child storage. (#7, #8, #16)
- `Mutex<T>` payloads and channel messages require `noBorrow(T)` and `sendable(T)`, not `shareable(T)`. Synchronized endpoints preserve concurrent operations and `Shared<Receiver<T>>`. `Shared<T>` itself requires both properties of `T` for cross-goroutine use; this still grants no ordinary mutable payload access. (#16)
- `lock(&counter)` acquires a goroutine-aware mutex and returns a non-copyable `LockGuard<T>` borrowing its source. `let mut held = lock(&counter); *held += 1i32;` uses built-in guard dereference, not a user-defined Deref trait or borrowMut accessor. Scope-exit/explicit disposal unlocks, not disposes the payload; protected borrows keep the guard needed. The guard is not sendable or borrow-free, but read-only sharing is allowed when T is shareable. Holding it across suspension/worker migration is allowed; self-reacquisition panics. There is no public raw unlock or callback-only withLock in v0. See `09-concurrency-safety.rill` and `09-concurrency-safety.md`; #23 finalizes `std::mutex::{Mutex, LockGuard, mutex, lock}` and explicit Shared forwarding. (#16, #23)
- `channel<T>(capacity)` takes explicit u64 capacity: zero rendezvous or a positive bounded buffer. It returns Sender/Receiver; last Sender closes, and buffered messages drain before None. Failed send returns the undelivered T in SendError<T>. `select` takes 2–4 receiver/handler pairs, commits one receive and invokes only its handler with Option<T>; closed/drained receivers are ready, with no priority/fairness promise. No string tags or losing-message race. Sleep/after use monotonic u64 milliseconds; no hard deadline. (#8, #16, #23)
- `std::routine` has plain `join`, fallible `all`, `allSettled`, `race`, and `any`, taking tuples of 2–4 owned once-capable jobs with appropriate transfer/borrow evidence. Results/error types must meet their explicit common-type rules; total any failure preserves all original envelopes. A winner/early failure cancels/joins remaining work before returning; caller cancellation also joins. Dynamic-sized helpers/variadic generics are deferred. (#16, #23)
- Native goroutines run on a parallel M:N scheduler and may migrate between OS workers; Wasm remains single-threaded. No user-visible OS-thread-affine resources, pinning interface, or public atomics in v0; runtime-internal atomics remain. (#16)
- Normal cancellation points include waits and compiler budget yields. Requests stay pending during disposal, invariant-sensitive replacement, and required cleanup joins; scheduling/completion continues, but cancellation cannot withdraw those deferred waits. Native jobs retain all borrowed sources until completion or confirmed abortion. Cleanup/blocking work/deadlock may delay stop/helpers indefinitely; no force kill or general deadlock prevention is promised. Panic remains immediate whole-program termination without cleanup. (#16)
- When top-level code ends, the program exits without an implicit global join or guarantee of background disposal. Use explicit stop/waiting when completion matters; a batch job or queue can keep the program alive by waiting on a channel. (#8, #16)
- `for ... of` uses canonical `std::iter::{iterate, next}` families; source expressions evaluate once. Standard and user-defined containers participate under ordinary orphan/checking rules. Consuming traversal moves elements, borrowed traversal retains sources, and exclusive yielded access ends before advancing. Mutable map traversal never grants mutable keys. Receiver traversal ends on closure/drain. (#23)
- Arrow expressions (`(x) => f(x)`), tuples (`[i32, i32]`), and destructuring (`let [a, b] = ...`) use TypeScript-style syntax. Callable types distinguish repeatable read-only `() => R`, repeatable exclusive `mut () => R`, and consuming `once () => R`. Infer the required mode; weakening is allowed, but annotations cannot strengthen invocation guarantees or erase borrow dependencies. Read-only invocation does not imply purity. Mutating owned captures requires mutable access to the closure. Invocation mode, borrow dependencies, and copyability are separate; erased arrows do not automatically prove `noBorrow` or `copy`. (#15)
- Named functions do not implicitly capture enclosing/top-level runtime `let` bindings, mutable or immutable. Pass state explicitly or use checked arrow closures; type/function declarations remain visible under module rules. Constant folding does not change binding access, and dispose/indirect calls cannot hide unchecked state. (#16)
- Every record has a declared nominal type and uses named construction, such as `let origin = Point { x: 0, y: 0 };`. No anonymous structural record types or values: neither a binding annotation nor a function parameter turns `{ ... }` into a named record. Inference from already typed expressions remains valid; no look-ahead or field-shape matching chooses a type. See [ADR 0008](../docs/adr/0008-records-require-named-construction.md) and `08-named-records.rill`. (#21)
- Record fields default to public; `private` fields are accessible only in their defining module. Any private field forbids external whole-record construction/rebuilding; aliases grant no new permissions. Genuinely private canonical types may cross exported operations as opaque inferred values, without external naming, construction, field access, or representation patterns. A public type lacking a local import name is not opaque. (#17)
- Enums are the only v0 sum types: `enum Language { English, French { crazy: string }, German(string), }`. Construct scoped unit/record/tuple variants with `Language.English`, `Language.French { crazy: "bonjour" }`, and `Language.German("hallo")`. No `A | B` types or mandatory literal `kind` tags remain. Each variant is nominal and its qualified name is also a usable type; constructors infer the variant, explicit parent annotations widen, and different-variant joins use the parent enum. (#19)
- Enums support ordinary generics/trailing defaults and payload/expected-type inference; an unconstrained payload-free constructor needs context or explicit type arguments. Exported enums expose all variants/payload fields, with no individually private variants/fields. Public payload types must meet public-interface visibility rules. Private enums can remain opaque; ordinary record privacy is unchanged. Owned/read-only variant access may widen to the parent enum, but `&mut Variant` cannot widen to `&mut ParentEnum`. (#19)
- `match (value) { pattern => expression, ... }` is an expression. Patterns can pull out fields, check nested values, use `_`, and take an `if` condition. The compiler rejects a `match` that misses a case.
- Enum patterns use qualified unit/record/tuple forms, such as `Language.French { crazy }` and `Language.German(text)`. Matching establishes the variant type of the scrutinee inside the arm, enabling its overload. Guards alone do not establish exhaustive coverage. Ordinary record-field and primitive-value patterns remain; literal expressions in patterns are not literal types. `{` after `=>` starts a block; a named constructor is an expression and needs no record-versus-block parentheses. A block arm in a `match` with a value must leave the function. (#11, #19, #21)
- `Point { ...point, x: value }` rebuilds a named record, preserving the existing ownership/copy rules and same-type owned-value reuse guarantees. Bare `{ ...point, ... }` is not an alternative construction form. (#21)
- Option/Result and tagged library results use enums, not record-member unions. Result.Err holds an opaque `Err<E>` wrapper with typed value/origin/optional unique Cause. Ordinary library records still need named construction. See the [catalogue](../docs/standard-library-contracts.md) for canonical paths, queries, consuming combinators, Bytes/text and I/O contracts. (#19, #21, #23)
- Constructing an Err records its origin; postfix propagation/returns/map/andThen preserve the wrapper without trace entries. `inner ? outerValue` lazily creates one new outer error caused by the original, then returns early. Retaining a cause requires display/noBorrow/sendable/shareable; a primary borrowed error can still be propagated directly. Default Error uses explicit `error(message)`, not implicit conversion from string. Canonical display formats a payload; standard formatting assembles the complete explicit chain with bounded traversal. (#23, #29)

## Numbers, text, and interpolation (#18)

[ADR 0011](../docs/adr/0011-explicit-numeric-widths-and-utf8-string-views.md) records the confirmed rules. `11-numbers-strings.rill` and `.md` are hand-checked examples/cases, not executed tests. Earlier examples now select i32/f64 explicitly; these are example choices, not defaults. The #23 catalogue now supplies concrete library interfaces; older spellings/layout sketches remain historical where its later decisions supersede them.

- Only i8/i16/i32/i64/i128, u8/u16/u32/u64/u128, f32/f64; no built-in int/float/byte/isize/usize aliases. An annotation, known parameter/return context, or suffix establishes literal width; no fallback or smallest-fit guess. #19 removes singleton types/refinements: literals have ordinary base types whose widths must still be established.
- Integers use decimal/binary/octal/hex literals, underscores and suffixes; floats use decimal fractions/exponents. Invalid individual literals reject, with signed-minimum negated literals supported. Unsigned negation is invalid. Float literals round nearest/ties-even, reject finite overflow to infinity, and may underflow to zero.
- Integer arithmetic checks overflow and zero divisors in every build; MIN/-1 and MIN%-1 panic. Division truncates toward zero; remainder has the dividend's sign. Bits use two's complement and u32 shift counts; invalid counts panic, left shifts discard bits, and signed/unsigned right shifts are arithmetic/logical. Wrapping/saturation is explicit. Well-typed constant expressions retain panic-if-executed semantics, not mandatory rejection; folding preserves effects/acceptance.
- Floats use IEEE values/arithmetic/comparisons, including non-trapping zero division and truncating floating remainder. No implicit result-changing fusion/reassociation or portable NaN payloads. Already-typed numeric operands do not implicitly convert.
- No numeric `as`. `from`/`into` alias one canonical infallible family; `tryFrom`/`tryInto` alias one canonical fallible Result-returning family. #41 / [ADR 0017](../docs/adr/0017-user-implementable-conversions.md) permits user implementations under its conversion-specific rules, not general return-only overloads or new traits. Standard numeric pairs remain protected, including fallible Ok results for safe pairs. Integer availability uses full base-type ranges, not a known fitting value. Float destinations may round/narrow to infinity without error; integer destinations from floats truncate then check range/non-finiteness. Infallible is not lossless.
- Conversion target/source generic arguments use normal contextual/partial inference without defaults; the source must independently have a width. Generic calls require canonical conversion evidence before monomorphization; #41 / ADR 0017 specifies the fallible implementation-defined error relationship. Fixture 11's generic conversion helper now names E with exact selected-error evidence; unrelated older helper sketches remain illustrative. Names need imports; other capabilities retain their own requirements. Numeric parsing is separate: known destination, Result, whole strict decimal input, no implicit trim/separators/suffixes/base prefixes. Finite parsing overflow errors; formatter special values and signed zero roundtrip to the original explicit width.
- Owned string is valid UTF-8 and moves unless explicitly copied. `&string` is a logical read-only whole/subtext view, not an assumed owner-header pointer; `&mut string` exclusively edits a whole owner, not a substring. Copying a view retains its dependencies; `copy(view)` copies exactly its text under #23's borrowed copy signature. Nested references distinguish descriptor storage from backing storage. Existing #15/#16 source, exclusive, retained-storage and cleanup rules remain; no writable-byte validity bypass or implicit counts.
- Direct string-literal expressions may be re-materialized into fresh logical owners, never by cloning freeable ownership. Named string bindings move unless explicitly copied; known contents grant no implicit-copy exception. Direct literal views can be static but remain borrowed for noBorrow; named-owner borrows/captures do not gain a folding exception.
- char is a four-byte Unicode scalar, not a byte/grapheme. Checked u32 scalar construction returns Option; code-point queries yield u32. Strings use u64 byte lengths/offsets, checked scalar-boundary Option views, borrowed byte/scalar traversal and checked byte lookup. No string character/range indexing. Owned bytes copy unless explicitly transferred; no assumed List layout/fake byte header. Strict UTF-8 decoding returns Result; lossy decoding explicitly replaces invalid sequences. Comparisons are non-consuming, exact/lexicographic, not normalized or locale-sensitive.
- Quoted chars/strings, templates and raw strings have the agreed escapes/scalar validity; raw text is not bytes. Ordinary quotes reject physical newlines; raw/templates allow multiline with no dedent. Source CRLF normalizes LF, unlike runtime text decoding. Interpolation uses canonical standard show (not a local namesake), requires support/evidence, and has explicit reference-forwarding implementations, not automatic dereference dispatch. Evaluate/format once left-to-right through read access, with normal temporary cleanup and owned output. No reflected private-field dump, prelude show injection, or early guard unlock.
- Default show emits unquoted text, lowercase bools, decimal integers, and shortest same-width roundtripping floats (NaN/inf/-inf/-0). Special formatting is explicit functions, not a template mini-language. Primitive canonical formatters must not recursively interpolate their own arguments. #19 removes literal types/overloads; #23 finalizes library paths and signatures.

## Open questions

- The combined checker/runtime is a proposal, not an implemented or demonstrated-sound system.
