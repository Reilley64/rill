# #30: native pre-write admission and a packet tail-ABI candidate

**Executed standalone C/LLVM23 mechanisms, not a Rill compiler/runtime or target
support approval. #30's standalone mechanism stage is complete; #28's production/formal gate remains OPEN.** See the [combined disposition](../../../docs/research/0030-runtime-validation.md). This supplements,
not replaces, `../README.md` and ADR 0014 / #22. Native `tailcc`/`musttail` remains
the direction. No public ABI/architecture adoption is implied.

## Reproduce

```sh
python3 prototypes/backend-30/native-capacity/run.py \
  --out /tmp/rill-30-native-capacity-final
```

locations, macOS SDK, installed Rosetta, and running Docker **29.8.2**. The runner
uses the two immutable official Rust image digests in `run.py`, with network

with GNU ld **2.44** / glibc **2.41**. Mac links use the SDK's Apple linker, not
LLD; LLD is inventoried, not claimed as the linker used. `switch.S` is a small
Clang-assembled platform stack bootstrap, not a GCC implementation of admission.

Recorded host: macOS **27.0.1 (26A434)** / Apple ARM64; Linux ARM64 kernel
**7.2.12-orbstack-00394-gbecdd6130068**, in the Docker VM. Rust images inventory
Rust **1.99.1**, but their Rust LLVM **23.1.1 is NOT used** to build mechanisms.
Mac x86 executes through Rosetta; Linux x86 executes through VM emulation. Neither
is physical x86 hardware validation.

## Actual native capacity experiment

`host.c` reserves a fixed, non-moving **4 MiB physical writable backing**, with
physical guards outside it. `switch_stack` enters at a fixed address 3 MiB into
that backing. The logical managed `NativeStack` is `[top-capacity, top)`, default
**1 MiB usable**. Sixty-four-byte canaries immediately below and above the logical
region are **inside writable physical backing**, not behind guard pages. Thus a
logical-region write can be detected even when physical guard pages do nothing.
The larger backing is deliberate test instrumentation, not extra usable capacity.
OS main stack, host scheduler state, mapping metadata and bootstrap saved
registers remain outside the guest region; there is **no pthread stack/TLS
metadata inside the capacity**. Guest return addresses, thunk and actual ABI
frames executing on the region do consume it. Addresses never move.

The pointer-only `admission(Context*)` is entered before the large callee **and
before the large argument-building caller**. It reads actual SP and checks
`bound <= SP-low` with prior SP range checks, before either prologue/copy can run.
The tiny thunk itself is bounded separately: tested precheck depth is 0–48 bytes,
minimum configured capacity is 4096 bytes (including return/red-zone slack).
At O2 the prologue may be shrink-wrapped *after* SP measurement. The bound
includes the thunk's complete `.su` frame even then; it does not mistake the
sampled SP for the bottom of the thunk's eventual frame.

The successful subtree actually executes:

- A **192 KiB**, **4096-aligned** builder frame, a **32 KiB by-value record**,
  caller-owned outgoing copy, and **32 KiB result temporary**.
- A **256 KiB**, **4096-aligned** callee frame, by-value argument inspection and
  result construction/copy. All record bytes and frame bytes are checked.
- Twelve distinct integer arguments, forcing outgoing stack arguments on both
  architectures; each argument's value/position is checked. The callee has external
  linkage so O2 cannot delete its constant scalar parameters via local argument
  promotion; the runner also checks that all twelve survive in emitted IR.
  x86 also passes the aggregate itself on
  the stack. AArch64's C aggregate ABI uses a pointer to a **caller-created stack
  copy**, not the rejected incoming LLVM `byval` tail convention.
- Separate freestanding memcpy/memset helpers generated by the same Clang23.

Bounds are computed per target/mode from actual Clang23 `-fstack-usage` files,
not source array sizes or SP samples alone. For the finite acyclic subtree the
runner sums all five potentially used helper frames (conservatively including
non-overlapping helpers), the entire thunk frame, **4240 extra bytes per node**
(4096 extra realignment + 128 red-zone + 16 return/link allowance), and **16 KiB
runtime headroom**. This deliberately double-counts some layout to be safe.
`.su` values of zero do NOT erase red zones/alignment. Dynamic/unknown frames,
recursive helpers, unknown native calls and indirect helpers are rejected by
the runner; LLVM intrinsics must lower only to the audited native helper set.
This subtree calls no OS/libc runtime. The bound is **fixture-specific**, not a
production Rill capacity formula or a bound on arbitrary runtime/native calls.

The generated assembly audit checks three SP/range/footprint conditional branches
before the first large call. The complete small thunk is retained in the compact
evidence. Object disassembly and full builder/callee assembly are in `/tmp`.
Large prologues reserve their frames before the first body check, exactly the
failure that a callee-only check would miss. No claim relies on guard pages or a
`probe-stack` attribute. The runner rejects unaccounted stack-probe helpers.

### Executed capacity outcomes (each of eight target/mode combinations)

- Default, near-threshold (+16 bytes), exact conservative admission fit: succeed;
  both adjacent canaries intact, full aggregate/frame/result checks pass.
- Exact capacity with required footprint **one byte larger**, capacity one
  16-byte alignment unit short, and minimum 4096-byte capacity: **fatal status
  86**, builder entry count zero, both canaries intact.
- A real **2 MiB / 4096-aligned** function's `.su` footprint exceeds default
  capacity: rejected by the outside thunk, entry count zero, canaries intact.
- Zero, below-minimum, above fixture maximum, UINT64_MAX, and UINT64_MAX-7:
  rejected by generated checked-u64 upward-alignment validation, before mapping.
  Request 1048561 rounds upward to effective 1048576 and executes successfully.
- **Unchecked control**: the real builder executes with logical capacity 128 KiB
  and corrupts the adjacent lower canary, while upper canary, computation and
  physical backing remain valid. This intentionally violates the logical
  contract without C/LLVM out-of-object writes or a hardware guard fault.

“Exact fit” is exact at the **conservative admission boundary**, NOT the actual
last byte touched. Measured successful sampled depths are about 564–572 KiB;
conservative bounds are about 601–609 KiB (exact bytes in evidence). SP samples do not claim to measure
all transient copy/prologue bytes; `.su`/assembly supply the bound. Near-limit
means near this fixture's admission threshold, not a universal recursion depth.
The minimum 4096, maximum 1 MiB, 16-byte capacity rounding and 16 KiB headroom are
probe constants, **not proposed #23 public configuration policy**.

### Fatal execution boundary

The rejection value is returned **only to the external embedding scheduler** via
the bootstrap. The host checks canaries on its original OS stack, emits bounded
fixture JSON, and `_exit(86)`s that isolated process. There is no guest caller,
Rill `Result`, guest recovery, guest continuation, unwind or user cleanup. The
normal-looking C integer is a harness scheduler ABI, not a recoverable language
API. Invalid settings follow the same isolated external termination convention;
Rill's build-setting diagnostic vs dynamic panic distinction remains unimplemented.
This uses the task's allowed scheduler-termination alternative: **no signal
handler is installed**, no allocation occurs in a handler, and no exhausted-stack
printf is attempted. A production trap/sigaltstack emergency report is NOT tested.

## Private ABI candidate: uniform earlier-owned packet / result buffer

`abi_root` ordinarily owns a fixed aligned `Packet` (257 data bytes plus an owned
buffer pointer) and a separate 257-byte result array. It makes an ordinary call
to the IR dispatcher. Internal eligible chains use identical signatures:

```llvm
define tailcc void @f(i64 %n, ptr %packet, ptr %out, ptr %ctx, ptr %fn)
; ... no alloca, byval, or per-step allocation ...
musttail call tailcc void %fn(i64 %nn, ptr %packet, ptr %out, ptr %ctx, ptr %fn)
ret void
```

The packet/result pointers refer to the **earlier ordinary root**, never an
alloca of the current eliminated caller. Root lifetime spans the chain. The
packet models a moved by-value source argument: each predecessor relinquishes
its ownership to its successor; dead earlier copies are not retained. The source
value need not be encoded with LLVM `byval`. Existing references, independently
live source copies or pending obligations would need separate storage and rules,
not permission to overwrite them. Intermediate callers owe no post-call cleanup.
The root's ordinary lifetime is intentional, not silently classifying an eligible
source tail as ordinary. No caller-local borrow is passed across mandatory tail.

Every self, mutual and actually indirect chain executes **1,000,000 transfers**
(**1,000,001 SP samples**) at O0 and O2. Each step updates a byte selected modulo
257. Final checks verify every byte of every data/result field against the exact
per-index update count. A **real 73-byte malloc-owned buffer** is manually moved
from host context to packet. The final callee checks its contents, frees it,
nulls the pointer and increments release count **exactly once**; root/host do not
free it again. This is manual ownership evidence, not #28 checker validation.
Its external libc `free` is NOT covered by the capacity subtree's finite bound.

All 24 chains had sampled **SP span 0 bytes**; sampled depth from region top was
704–896 bytes. Generated code has direct tail branches for mutual calls and
register-indirect branches for indirect calls at both modes; O0 self is a tail
branch, O2 self is transformed into a loop. The runner checks there are no
ordinary recursive calls. No allocation is possible in the per-step IR or SP
sampler: packet/result/context are fixed, only the one owned data allocation
exists, and final disposal occurs once. There is no heap activation history.

The original incoming LLVM `byval([32 x i64])` shape is still verified as valid IR
and **rejected by AArch64 codegen** at both modes on both OS targets. x86 codegen
accepts it; that negative-control IR is never executed here. This rejection is
preserved evidence, not a reason to weaken source by-value or proper-tail rules.

### Structural reach and gaps

Uniform pointers avoid register splitting/byval/sret signature mismatch for an
arbitrary **known fixed-layout unboxed record**: bytes can live at the right
alignment in an earlier ordinary owner, with explicit result storage and a common
tail signature. A finite statically known tail component could conservatively
reserve maximum packet/result size/alignment before entering it. This is a
mechanism argument, **not an executed arbitrary-record ABI implementation**.
Only one packet layout, one 257-byte result layout, a byte update and one moved
resource were executed. Different layouts, independent source copies, enums,
large/high-alignment fields, overlapping argument/result aliasing, polymorphic
indirect dispatch, larger cross-signature transitions, native/public interop,
escaping packet pointers, source drop elaboration and admission of those copies
still require design/checker/lowering work. No scalarized-SSA candidate is tested.
No current-callee alloca can be rescued by calling it a packet.

heap activation substitution, architecture approval or backend support closure is
claimed. Parent-owned lifecycle and portable probes remain separate.
