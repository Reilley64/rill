# The i32 equality root and the O15 expectation (ri-785.9, 2026-11-23)

This is ticket B6, under owner decision D2 (b). It re-lands the installed `implement eq(left: &i32, right: &i32): bool { return *left == *right; }` source root of `stdlib/compare.rill` from `a6271cc` (kept on `checkpoint/m5-with-equality-7b76ded`, parked by `4c114f6`). It also lowers `left == right` on two `i32` operands, so RFC 0007 case O15's `expect counter() == 12i32;` is a `Checked` root with MIR. The MIR calls `counter`, initializes `12i32`, compares the two values with `EqualI32` and exports the result. Nothing runs, so the value 12 is not observed; that needs execution (M6).

## What changed

- **Tightened eligibility screen** (from `tmp-2026-11-22/rill-66-2ff816a-budget-design.md`). Before any charge, both query paths read the written header of a `compare.rill` implementation: a fixed number of syntax nodes, no facts and no lookups. Only `eq(left: &i32, right: &i32): bool` passes. Every other width and the generic `&&T` adapter keep their pre-equality early exit: 9 / 0 / 0 targeted, and uncharged `Pending` in the graph. The equality frame then needs the typed equality family, the canonical signature and the `I32` equality provider, as `a6271cc` did. The body's fixed depth 5 is checked before the body is inspected. At `2ff816a` the root cost 329 work in every graph. 13 of that was one step for each of the 13 other `compare.rill` bodies, which the screen removes.
- **M4 fact `i32_equality`**. The scalar facts pass marks `left == right` with a `bool` result when each operand, through groups, is an `i32` call, or an `i32` operand that M5's checked arithmetic reads (local, literal, bounded product or sum). It is classified from operand classes and types already inferred, and charges nothing. The M4 caps are unchanged: `legacy_caps` replays every typed row, including the 17-source baseline at 372,246 / 54,059 / 12.
- **M5 lowering**. On that fact, M5 lowers the left operand, then the right, into scratch slots. `EqualI32` ends both slots and initializes the result. Groups add depth, not operations.

Commits: `2445b3a9` (source and tests), `437e31f8` and the commit after the base merge (whole-graph re-pins), and this record.
