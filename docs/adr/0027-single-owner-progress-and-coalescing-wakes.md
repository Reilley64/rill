# Single-owner progress drivers and coalescing wakes

Rill’s ordinary I/O suspends with exclusive caller buffers and TLS deliberately has one application-I/O owner, so readiness followed by an arbitrary blocking call, TLS splitting and cancellation-as-yield cannot support general bidirectional streaming safely. Use concrete single-owner progress drivers that admit owned bounded work, advance locally without external waits, retain native retry state/results, and register one-shot coalescing wake hints over authoritative state. Channel try operations and readiness watches keep the sole coordinator out of blocking sends/receives; explicit family/output evidence preserves Rill’s no-trait model. Futures/Poll, public descriptors, dynamic registries, associated errors and raw owner recovery remain excluded.

## Consequences

Ordinary read/write/flush/close remain unchanged and do not imply progress capability. TCP may run private opposite-direction jobs under one owner; TLS selects its BIO/mode profile before handshake and never exposes independent drivers. Controls stay in the coordinator: app/timer wakes withdraw registrations without abandoning I/O, while true terminal control requests joined stop. Bounded pressure is pending; bounded-state impossibility is typed failure; no deadline or wake promises finite completion.

The selected OpenSSL profile uses fixed16KiB native attempts/BIO rings inside existing64KiB directional ceilings. A fixed private observer terminally stops on TLS1.2 post-handshake renegotiation: the pinned reference falsified an expected immediate BAD_WRITE_RETRY but demonstrated that unsafe local continuation can omit warning ciphertext, advance record state and cause peer record failure. The later [#39 HTTP contract](../http-contracts.md) uses one explicit runner and bounded app endpoints over this driver; it does not add a TLS split or claim implementation. This reference is not runtime/provider delivery. #47 and #44 retain implementation, asynchronous accounting and target acceptance.
