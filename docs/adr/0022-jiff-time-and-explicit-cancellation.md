# Jiff-derived time values, explicit clocks and source/token cancellation

ri-j60 adopts Jiff's calendar/zone model through Rill-native checked functions, separates wall timestamps from suspend-inclusive monotonic deadlines, and adds explicit source/token cancellation without public callbacks or a generic withCancellation wrapper. The user explicitly confirmed the consolidated Q1–Q91 design, then Q92's explicit std::env::Inputs argument for system-zone discovery. These are design inputs, not library/compiler implementation, executed Rill tests, a safety proof, backend support or accepted RFC.

The full [date/time contract](../time-contracts.md) and [clock/cancellation contract](../clock-cancellation-contracts.md) are authoritative. Jiff 0.2.44 is a pinned semantic reference, **not a dependency/FFI selection**. Gregorian civil values, unit-preserving calendar spans and exact elapsed quantities remain distinct; immutable retained zones keep their rules independently of database generations. Explicit database sources/quotas trade automatic host freshness for predictable authority and updates. Q92 prevents Jiff-style live getenv discovery from bypassing ri-7ap's safe startup inputs.

## Non-obvious adaptations

- Prefer checked public operations, exact integer boundaries and explicit context/rounding. Do not silently truncate Date arithmetic remainders, minute-round offsets, clamp leap seconds, ignore annotations or reproduce a negation-first false subtraction overflow. Canonical text is not original spelling, arbitrary Span field preservation or complete rules-dataset persistence.
- Default elapsed time counts OS suspend but neither wakes the machine nor promises accuracy/return latency. Typed clock factories fail when the host cannot honor this profile. Opaque instants have clock identity; arithmetic never wraps/rebases/clamps mismatches. Manual clocks control readings **and registrations**.
- Retain ri-8n7's old millisecond call shapes. New typed waits explicitly take a token and use WaitError; error-free legacy calls panic rather than fake success, silent closure or unsupported infinite waits. Clock eligibility, selected outcome and completed cleanup remain distinct.
- Source grants cancellation authority; token only observes a permanently one-shot state. Owned explicit copies retain state/authority, not stack borrows. Directed children/OR links propagate requests but do not own arbitrary operation completion. Ordinary disposal does not cancel; an explicit unique cancel-on-disposal guard can request, never join.
- Q53's no-token recommendation was superseded by the user's C#/Tokio direction. Q64's generic withCancellation proposal was then explicitly **removed**. Q62/Q63/Q65 remain included: guard, poll/wait/select observation and std::cancel. No callback registry, ambient context, mask controls, source CancelAfter/reuse or catchable cancellation exception is imported.
- Preserve withDeadline's exact R result, once/send evidence, valid scoped borrows, preflight and unspecified ready ties. Cancel/join losing work before return; explicit token outcomes do not become implicit goroutine cancellation or erased error conversion. Required native sources outlive actual completion/confirmed abort, and masking cannot be bypassed to abandon them.
