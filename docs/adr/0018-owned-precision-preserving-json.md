# Owned, precision-preserving JSON with explicit limits

[Issue #31](https://github.com/Reilley64/rill/issues/31) confirms `std::encoding::json` as a whole-document, fully owned value library with validated numeric text, unique insertion-ordered object names, strict scalar-safe input and explicit parse/format limits. Preserve JSON data without silently passing large numbers through f64 or making application records depend on the input buffer. The consolidated interview was explicitly confirmed; this is design input, not a parser implementation, compiler/checker proof or accepted feature RFC.

The complete [JSON contract](../json-contracts.md) supplies public types, APIs, errors, budgets and citations. It extends the [core catalogue](../standard-library-contracts.md) without adding reflection, derive, traits, streaming I/O or general serialization machinery. Conversion registration and generic error evidence are separately [confirmed in #41](https://github.com/Reilley64/rill/issues/41#issuecomment-6886119679); consume that decision without re-deciding or claiming to implement it here.

## Decisions and tradeoffs

- Value is a nominal enum of Null, Bool, Number, String, Array(List<Value>) and Object(Object). Number/Object are opaque; owned strings/names/arrays survive input release. Explicit deep copy preserves spelling/order, with no writable invariant fields, implicit snapshots or borrowed-DOM variant.
- Number retains validated JSON token text, not a primitive approximation. Text construction checks one exact token, consumes/copies according to source ownership and has no inherited document quota. No bigint arithmetic, normalization or semantic equality/hash API is implied.
- Exact integer extraction checks integrality/range without f64; float extraction explicitly rounds but rejects overflow to infinity and preserves negative zero. Primitive construction emits exact integer/same-width-roundtripping finite float text. Use the requested tryInto/tryFrom integration, while #41 owns declarations, concrete error mapping, registration, alias/coherence and generic evidence rules.
- Parse one complete RFC-grammar value, including scalars, with only JSON whitespace. Reject duplicates after escape decoding, comments, trailing commas/data, a leading BOM and unpaired surrogate escapes. Preserve valid scalar content/noncharacters without normalization. This intentionally differs from unrestricted grammar admission and the full stricter I-JSON profile.
- Object preserves insertion order independently of ordinary unordered Map. New names append; replacement retains the name/position and returns the old value; removal/reinsertion appends. Mutable views permit value changes, not stored-name mutation.
- Compact/pretty emit valid UTF-8 with deterministic minimal escaping, original number tokens and member order. Pretty defaults to two spaces/LF, inline empty containers and no terminal newline. This is not canonical JSON or HTML/JavaScript embedding escaping.
- Parse defaults: 16 MiB input, depth 128, one million values, 1 MiB decoded bytes per string/name and 1,024 number-token bytes. Format defaults: depth 128, 16 MiB emitted UTF-8. Inclusive independently configurable limits, meaningful zero, fixed-arity default/configured operations and named records/functions, not optional arguments or exported runtime globals.
- Fail fast, never truncate/repair/accept a partial document or return partial formatted output. Small structured errors own only kind/position/limit data; JSON byte offsets are distinct from error construction origins. UTF-8 validation remains explicit at the Bytes boundary.
- Limits do not promise exact heap usage, hard deadlines or recoverable allocation failure. Standard parse/format/copy/dispose and partial/canceled/deep-tree cleanup must have bounded call stacks even for programmatically built trees and raised limits, following #22/#23; #28/#30 still validate the mechanisms.

## Alternatives and evidence

Rejected eager f64 normalization, unchecked public number strings, last/first-wins parsing, unordered output inherited from Map, silent surrogate replacement, JSON5/prefix parsing, reflected/trait serialization, recursive stack exhaustion as a depth check and hidden partial output. Keep explicit application conversions and defer arithmetic/equality/canonicalization/streaming rather than infer them from preserved numeric text.

[Prototype 19](../../prototypes/19-json.rill) and its [case inventory](../prototypes/19-json.md) are hand-checked design fixtures, not executed tests. #41 owns conversion machinery, #24 diagnostics, #28 full RFC algorithms/checker/evidence/cleanup integration, and #30 backend gates. Any unworkable required rule returns to the map; closing #31 neither clears those gates nor implements JSON.
