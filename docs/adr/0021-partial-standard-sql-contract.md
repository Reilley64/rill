# Standard SQL execution with typed codecs and honest errors

**Status: human-confirmed shared-interface design.** The user confirmed the Q1-Q57 checkpoint, then Q58-Q77 and the final consolidated integration after [#33](https://github.com/Reilley64/rill/issues/33) closed. [#40](https://github.com/Reilley64/rill/issues/40) now completes design only, not a SQL implementation, checker/protocol/security proof or accepted feature RFC. The historical partial filename is retained for links. ADR 0020 records #37's secure-random decision; [#43](https://github.com/Reilley64/rill/issues/43) separately tracks the unfulfilled embedded native-provider prerequisite.

Place the shared SQL execution interface in `std::sql`, with canonical driver-facing families under `std::sql::driver` and identity-preserving exports/helpers. The user rejected the proposed external common execution library. Drivers and concrete pools remain external; static concrete connectors/types and ordinary pre-monomorphization family evidence replace assumptions of Go interfaces, runtime registration or public dyn. Keep SQL, dialect, ORM and schema-generation machinery external. Do not promise universally portable SQL or inspect ordinary closures.

[The integrated contract](../sql-contracts.md) records the agreed value and resource model: owned arguments/rows/prepared descriptors, a common Parameter subset with open concrete driver codecs, typed NULL/exact decimals, explicit into/tryInto binding/extraction, one statement/result stream, strict row cardinality, finite configurable limits, managed transaction guards and conservative reuse. Owning values carry explicit noBorrow evidence; scoped helper restrictions do not prohibit all direct borrowed errors. Native/server preparation resources belong to bounded session state, not dangling descriptor pointers.

Unique violations are first-class typed errors preserving native Err<E>. They can name qualified keys and ordered columns when established, but must explicitly report unavailable information. Current backend contracts cannot guarantee every column list. Expression keys are not ordinary column constraints. Metadata enrichment is explicit, provenance-aware and fallible. Standard formatting does not print native/codec payloads, values or SQL by default; retaining typed diagnostics is not automatic Cause erasure. These choices follow [primary-source research](../research/0040-standard-sql-and-unique-errors.md), not unsupported claims about library popularity or portability.

Commit/rollback consume guards and report confirmed committed/rolled-back/unknown outcomes separately from session disposition. Abandoned transactions discard; result abandonment requires positive cleanup/reuse evidence. External pools validate/reset candidates, and no standard operation is automatically replayed. Intrinsic cancellation remains outside Result; explicit token-aware SQL can return typed cancellation/expiry/clock errors only after required release. Owned SqlControl pairs an optional clock/Instant with a token, is consumed per operation and copied explicitly without restarting timeouts. Cursors retain query control; sessions/idle transactions do not inherit it. Canonical close/mandatory cleanup ignore external control and may wait indefinitely without proving rollback, native abortion or safe reuse.

Common Date/Time/DateTime/Timestamp parameters reuse #33's actual types, with exact range/precision and original TimeError preservation; zones/calendar intervals/elapsed durations require explicit native/schema mappings. The narrow std::time::validateInstantDomain follow-up checks private domain compatibility without reading time/registering timers, avoiding cross-module private access. Control preflight, terminal-row behavior, fixed operation arities, reset and separate phase-error relationships are specified in the contract.

JSON already permits application conversions to/from std::encoding::json::Value under #31/#41. Add explicit examples, not another Serializable trait or structural mapper. SQL's named conversion-aware binding is a narrow library integration, not implicit casting/chaining/registration. Do not overwrite separately prepared JSON artifacts or confuse their historical numbering with these streaming/SQL files.

## Alternatives, integration and remaining validation

- **External common execution module.** The user rejected this in favor of a Go-style standard interface. This does not move Go's concrete pool/registry into std.
- **One closed universal SQL value/error type:** rejected as a ceiling. A common parameter subset and structured error categories coexist with concrete driver values/errors and typed user codec failures.
- **Guaranteed nonempty unique-column list for all drivers:** rejected in favor of honest known/unavailable/provenance information; no message parser is promoted into a guarantee.
- **Implicit serialization/SQL rewriting/automatic retries:** rejected. Callers choose conversion helpers, dialect logic and reconciliation policies explicitly.
- **Ambient/inherited controls or a restarted relative timeout:** rejected. Explicit copies retain absolute targets; #33's withDeadline stays joined and preserves nested Results, not an implicit SQL token wrapper.
- **Cross-module access to clock identity:** rejected in favor of the explicitly approved public validateInstantDomain amendment, without exposing IDs or reading clocks during domain-only validation.
- **Embedded native provider as a shared-interface completion blocker:** explicitly split into #43. That contract/validation is not fulfilled and still gates claims of embedded support, but not shared-interface design closure/RFC drafting. No general FFI, raw pointers, public pinning or working SQLite adapter is authorized by the split.
