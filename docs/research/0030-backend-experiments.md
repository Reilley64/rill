# #30: executed backend mechanism experiments

2026-11-15. The support gate remains open. These finite standalone experiments provide positive mechanism evidence and reproducible counterexamples. They do not implement Rill or prove arbitrary-depth behavior, checker correctness, complete ABI/runtime semantics or provider integrations. They do not establish RFC acceptance. No target or contract has been dropped, weakened or silently replaced.

See the [pinned official-source audit](0030-backend-mechanisms.md), [reproduction instructions and source inventory](../../experiments/backend-30/README.md), [recorded observations/hashes](../../experiments/backend-30/evidence/results.json) and [exact issued commands/exit codes](../../experiments/backend-30/evidence/commands.json). Commands generate the IR/assembly/WAT and retain full stdout/stderr in the selected output directory. The issue publication archives those text artifacts and the source snapshot, excluding binaries/tools. GitHub publication is not a claim the local branch has been committed or pushed.

All tail cases verify call counts and results, not merely survival. The still-live root ordinary caller owns the sret buffer; tail callees forward that earlier storage. Native probe IR has no heap activation allocation; assembly contains direct sibling branches/indirect branch transfers (O2 may replace some self cycles with loops). Wasm WAT retains direct/indirect `return_call` where required. The async sampler completes before each transfer; continuation finalizers balance callbacks before the next one. Constant-size counters avoid retaining one sample per call. None of these observations proves every temporary peak, engine allocation, signature or arbitrary chain length.

## Why the prior pipeline cannot clear the gate

1. Proper tails remain incompatible with stock Asyncify. LLVM can emit valid Wasm return calls using a supported convention, and Wasmtime can execute them with its own host fibers, but stock Asyncify rejects them. Replacing return calls with ordinary calls is not a fix: the ordinary control saves 476 / 3,612 / 28,700 bytes at depths 16 / 128 / 1,024. That is a control demonstrating retained ordinary history, not a proposed lowering.
2. Managed-region containment is also missing. The saved-region test corrupts neighboring in-bounds storage before trapping; the leaf red-zone test corrupts neighboring storage without trapping. Overall memory bounds and checking only stack-pointer assignments do not satisfy #22. Additional accounting/checks must cover frames, padding, arguments, return buffers, runtime/native entry and saved pushes before writes, with checked arithmetic. Guard pages and host limits do not supply that mechanism.
3. The ABI is not uniformly established. AArch64's incoming-byval rejection is concrete. Passing scalar, small-aggregate and explicit-return-buffer candidates does not authorize a silent signature exception or ordinary-call fallback. A complete Rill ABI/lifetime explanation remains necessary.
4. A host-specific positive result does not select a portable architecture. Wasmtime async fibers retain native frames rather than Asyncify's serialized state. Correctly charging all retained activation storage against Rill's separate managed saved budget, and the intended WASIp1/browser/embedding deployment scope, remain unresolved. One configured 1 MiB host fiber is not that accounting proof.
5. The experiment code does not implement the runtime obligations. No compiler exists here to generate masks, protected cleanup, remaining-field actions, source eligibility checks, native leases or M:N scheduling. The copying control is a valid retention mechanism for its bytes, not implementation of all borrowed results/zero-copy/native adapters or same-store concurrent growth. Models explicitly preserve their declared ordering/pending-state rules, not an unimplemented language runtime.

## Next gate and handoff

Keep #30 open and #28's affected backend/lowering constraints not implementation-ready. #13/#23/#24 consume ABI/cleanup/diagnostic evidence without reopening their approved public contracts: unsupported genuinely eligible tails reject (R0600); valid ordinary calls remain valid; no false front-end/LSP success implies backend validation. Clock/token/I/O/filesystem/SQL/TLS provider and native-registration gates remain untouched.

Before adopting a replacement, request a human architecture/scope decision through the issue map. The options are to retain the portable Wasm contract and authorize investigation of a tail-compatible suspension/managed-budget mechanism, or to review a host-specific profile and its accounting/deployment implications. This report recommends retaining the approved semantics/targets and rejecting the old pipeline as established support. It does not select a new compiler architecture, make a target drop, accept ordinary fallback, transfer the blocker, or claim a human decision has happened.

After candidate approval, test large/near-limit frames and arguments with canaries/probes, and cover complete aggregate/result shapes. Exercise per-routine saved-state accounting with multiple routines under the program-wide setting. Test native stack migration/borrower leases, cancellation/reclamation through actual completion, and production cleanup order/suspension/masking/joins. Add physical-hardware/platform execution where it is absent. The checked-in runner is a reproducible starting point, not completion of those obligations.
