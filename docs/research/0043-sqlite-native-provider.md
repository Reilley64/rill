# #43 primary-source evidence: SQLite native-provider constraints

Research and selected-source audit informed the explicitly confirmed [contract](../sqlite-provider-contracts.md); they did not choose a general FFI, dependency before confirmation, or certify native support. Read-only delegated investigations made no issue/file changes; the final confirmed phase added the reproducible [reference harness/report](../../prototypes/26-sqlite-provider/reference/results.md). All claims below have narrower scope than a Rill integration proof.

## Verified pin and release-specific findings

On the recording investigation, the [official download page](https://sqlite.org/download.html) advertised 3.54.1. Official [archive](https://sqlite.org/2026/sqlite-amalgamation-3540100.zip): 2,990,966 bytes, SHA3-256 `92281c86e2957f9b9305890f9ac04204caa7b677cc868dc326d942689df28e30`. Downloaded digest/size agreed. sqlite3.c/header report sourceID `2026-10-16 14:45:20 555e07ef33f69a0957d24d8e555b702464a131d6f1607f4c3c1e4551e8e6ca76`; sqlite3.c SHA3 `e2b869d3003b33c942b7dd7063604fbc53553e1b66609570df39b9b7b558ee81` agrees with the [release page](https://sqlite.org/releaselog/3_54_1.html). Digest comparison identifies source against upstream's published values, not independent supply-chain/security assurance.

The [chronology](https://sqlite.org/chronology.html) also lists 3.53.6/3.50.8/3.44.7 maintenance releases dated 2026-11-13; they are not the same as the advertised mainline download. [Changes](https://sqlite.org/changes.html), [SQLite's CVE assessment](https://sqlite.org/cves.html) and [WAL-reset notice](https://sqlite.org/wal.html#the_wal_reset_bug) require profile-specific review: historical 3.50.4 predates WAL-reset fixes; optional FTS issues and 32-bit issues have specific applicability, not a blanket dismissal of all risk. 3.54.0 also changed DEFAULT-clause function authorization. Do not attribute current documentation to older references without checking source.

The [batch-atomic fallback fix](https://sqlite.org/src/info/75ad951b1b) landed after 3.54.1. Selected source lacks the added `syncJournal(pPager,0)` after fallback journal creation; despite check-in wording about the db file, the added call synchronizes the materialized rollback journal. Related [3.53 backport](https://sqlite.org/src/info/272d90d7f3), [3.50 backport](https://sqlite.org/src/info/5444d67e67), [3.44 backport](https://sqlite.org/src/info/feca97beee) explain the later maintenance context. ENABLE_BATCH_ATOMIC_WRITE is presence-tested: **undefined**, not zero, excludes this path. This is a narrow applicability finding, not assurance about every durability defect.

## Native lifetime and execution facts

| Area | Primary evidence / consequence |
| --- | --- |
| Open/prepare | [open](https://sqlite.org/c3ref/open.html) can return nonnull handle on failure; capture diagnostics/close it. [prepare](https://sqlite.org/c3ref/prepare.html) compiles first statement and returns a tail; v2/v3 retain SQL/reprepare. Prefix success does not validate whole input. |
| Binding | [bind](https://sqlite.org/c3ref/bind_blob.html): TRANSIENT copies before return, STATIC survives reset until rebind/finalize, destructor failure paths matter. Null pointers can mean NULL, zero-length BLOB needs care. |
| Slots | [parameter count](https://sqlite.org/c3ref/bind_parameter_count.html) is maximum index; ?NNN creates gaps and repeated names share indices. [names](https://sqlite.org/c3ref/bind_parameter_name.html) cannot distinguish all anonymous/gap cases. Unbound slots are NULL; never use this to fill omitted application arguments silently. |
| Columns | [accessors](https://sqlite.org/c3ref/column_blob.html) have ROW/state/ordinal requirements; conversions/step/reset/finalize invalidate pointers. Initial storage class must be read before conversion. OOM can resemble NULL. Copy before invalidation, check encoding/types/ranges. |
| Diagnostics | [error APIs](https://sqlite.org/c3ref/errcode.html): messages/codes are mutable connection state; later calls invalidate them, FULLMUTEX alone does not serialize error→copy. MISUSE need not have valid diagnostics. Stock fields do not identify a guaranteed failing unique key; see [#40 research](0040-standard-sql-and-unique-errors.md). |
| Reset/finalize | [reset](https://sqlite.org/c3ref/reset.html) preserves bindings and can report prior or new completion error, including RETURNING followed by BUSY. [finalize](https://sqlite.org/c3ref/finalize.html) destroys even on error; never retry the pointer. |
| Close | [close](https://sqlite.org/c3ref/close.html): BUSY leaves connection alive; close_v2 can create a zombie with deferred destruction. OK does not then prove all children/resources destroyed. |
| Interrupt | [interrupt](https://sqlite.org/c3ref/interrupt.html) may run from another thread but close must not race its use; requests may lose completion races, idle request is no latch, effects can extend across running statements. Automatic DML rollback is context-specific, not a universal cancellation guarantee. |
| Callbacks | [progress](https://sqlite.org/c3ref/progress_handler.html) is approximate/also preparation; [busy](https://sqlite.org/c3ref/busy_handler.html) can be skipped and is non-reentrant; [timeout](https://sqlite.org/c3ref/busy_timeout.html) counts sleeps, not overall operation deadline. No hard abortion of arbitrary VFS work is guaranteed. |
| Threading | [thread modes](https://sqlite.org/threadsafe.html), [threadsafe](https://sqlite.org/c3ref/threadsafe.html): compile/startup/connection layers differ. Compile-time 0 cannot be escalated. Sequential calls can move threads, but shared mode does not protect complete copy/lifetime sequences. |

## Selected-source policy audit (3.54.1, not only historical 3.50.4)

Source references: [pragma.c](https://sqlite.org/src/file/src/pragma.c?ci=version-3.54.1), [auth.c](https://sqlite.org/src/file/src/auth.c?ci=version-3.54.1), [build.c](https://sqlite.org/src/file/src/build.c?ci=version-3.54.1), [vdbe.c](https://sqlite.org/src/file/src/vdbe.c?ci=version-3.54.1), [pager.c](https://sqlite.org/src/file/src/pager.c?ci=version-3.54.1), [pragma.h](https://sqlite.org/src/file/src/pragma.h?ci=version-3.54.1). APIs: [authorizer](https://sqlite.org/c3ref/set_authorizer.html), [actions](https://sqlite.org/c3ref/c_alter_table.html), [PRAGMAs](https://sqlite.org/pragma.html), [statement readonly](https://sqlite.org/c3ref/stmt_readonly.html).

- PRAGMA auth happens before VFS dispatch and name lookup, including unknown names. Schema resolution/explicit-temp opening can happen earlier. IGNORE is not general rejection; callback strings can be NULL/case-arbitrary.
- Argument presence is not read/write classification: table_info(table) needs an argument, while noarg checkpoint/optimize can have effects. query_only/foreign_keys/trusted_schema assignments mutate during prepare; EXPLAIN/readonly checking after prepare is not a barrier.
- The accepted built-in inspections do not intentionally assign settings/data but can load schema, resolve views/virtual tables, invoke xConnect, lock/recover or return filesystem paths. VFS PRAGMA interception comes first. Selected-source view-column derivation temporarily disables xAuth around result-column resolution; do not claim complete underlying ACL coverage.
- Selected pragma table-valued forms exist and prepare their direct PRAGMA in xFilter during outer evaluation, so authorizer must stay installed through stepping. Hidden arguments differ: table_list has filter only, object inspectors object/schema, journal_mode/synchronous schema only, listed other observations no hidden args.
- Authorization is not normally repeated on every cached step. Reprepare runs it again. Changing callback-owned policy data alone is not a cache invalidation protocol. Current query_only is checked at native write transaction start, including cached writes, but not a proof about every mutable policy.
- Semantic transaction/savepoint/ATTACH/DETACH actions can reject categories; they do not prevent implicit transactions, ON CONFLICT ROLLBACK or automatic rollback. ATTACH auth argument can be NULL for runtime filename expressions, not a generic evaluated path guard.
- PRAGMA busy_timeout changes busy handling; threads changes a sqlite3_limit; heap limits are library-global. Defensive/trusted-schema settings have narrower semantics and SQL counterparts, not a general configuration freeze or sandbox. Removing extension loading does not remove compiled-in modules.

## Values, transactions and platform boundaries

[Datatypes](https://sqlite.org/datatype3.html), [floating point](https://sqlite.org/floatingpoint.html) and [STRICT](https://sqlite.org/stricttables.html): native INTEGER=i64, REAL=binary64; no Decimal/calendar storage classes. Affinity/casts/SQL may change values even with STRICT. NaN native bind becomes NULL in selected source; the product must reject it. Native getters alone are not checked conversion evidence.

[Isolation](https://sqlite.org/isolation.html): serializable except dirty reads require BOTH shared cache and read_uncommitted. WAL snapshots can fail promotion with BUSY_SNAPSHOT. [query_only](https://sqlite.org/pragma.html#pragma_query_only) is not a physically read-only/sandbox connection. [autocommit](https://sqlite.org/c3ref/get_autocommit.html) says whether explicit transaction survived, not commit history or absence of unfinished implicit work; [txn_state](https://sqlite.org/c3ref/txn_state.html) supplies separate observations. Read these under exclusive access.

[Initialization](https://sqlite.org/c3ref/initialize.html)/[configuration](https://sqlite.org/c3ref/config.html) are library-global and lifecycle constrained. [Amalgamation](https://sqlite.org/amalgamation.html)/[compile options](https://sqlite.org/compile.html): internal static linkage does not hide every public API/global. [GNU loader hardening](https://sourceware.org/glibc/manual/latest/html_node/Dynamic-Linker-Hardening.html), [GCC visibility](https://gcc.gnu.org/onlinedocs/gcc/Code-Gen-Options.html), [ld](https://sourceware.org/binutils/docs/ld/Options.html), [objcopy](https://sourceware.org/binutils/docs/binutils/objcopy.html) show available techniques, not portable Rill isolation. Our one-host object audit is narrower than product build/link/loader evidence.

[Database mmap](https://sqlite.org/mmap.html) and selected [Unix VFS source](https://sqlite.org/src/file/src/os_unix.c?ci=version-3.54.1): MAX_MMAP_SIZE=0 removes database-file mapping, not WAL shared-memory mapping. [VFS](https://sqlite.org/vfs.html) controls files/locks/sync/random/time and sidecars beyond main path. [WASIp1](https://github.com/WebAssembly/WASI/blob/snapshot-01/phases/snapshot/docs.md) rights/locking/import limitations require a separate profile; [SQLite Wasm goals](https://sqlite.org/wasm/doc/trunk/about.md) are browser/JS-oriented, not WASI compatibility. No profile or import is approved by the existence of an old SQLITE_WASI source branch.
