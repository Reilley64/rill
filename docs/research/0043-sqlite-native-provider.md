# #43 primary-source evidence: SQLite native-provider constraints

Research and the selected-source audit informed the explicitly confirmed [contract](../sqlite-provider-contracts.md). They did not approve general FFI, choose a dependency before confirmation or certify native support. Read-only delegated investigations made no issue/file changes; the final confirmed phase added the reproducible [reference harness/report](../../experiments/sqlite-provider/reference/results.md). All claims below have narrower scope than a Rill integration proof.

## Verified pin and release-specific findings

During the recorded investigation, the [official download page](https://sqlite.org/download.html) advertised 3.54.1. Official [archive](https://sqlite.org/2026/sqlite-amalgamation-3540100.zip): 2,990,966 bytes, SHA3-256 `92281c86e2957f9b9305890f9ac04204caa7b677cc868dc326d942689df28e30`. The downloaded archive matched that digest and size. sqlite3.c and its header report sourceID `2026-10-16 14:45:20 555e07ef33f69a0957d24d8e555b702464a131d6f1607f4c3c1e4551e8e6ca76`; sqlite3.c SHA3 `e2b869d3003b33c942b7dd7063604fbc53553e1b66609570df39b9b7b558ee81` agrees with the [release page](https://sqlite.org/releaselog/3_54_1.html). Digest comparison identifies source against upstream's published values, not independent supply-chain/security assurance.

The [chronology](https://sqlite.org/chronology.html) also lists 3.53.6/3.50.8/3.44.7 maintenance releases dated 2026-11-13; they are not the same as the advertised mainline download. [Changes](https://sqlite.org/changes.html), [SQLite's CVE assessment](https://sqlite.org/cves.html) and [WAL-reset notice](https://sqlite.org/wal.html#the_wal_reset_bug) require profile-specific review: historical 3.50.4 predates WAL-reset fixes; optional FTS issues and 32-bit issues have specific applicability, not a blanket dismissal of all risk. 3.54.0 also changed DEFAULT-clause function authorization. Do not attribute current documentation to older references without checking source.

The [batch-atomic fallback fix](https://sqlite.org/src/info/75ad951b1b) landed after 3.54.1. Selected source lacks the added `syncJournal(pPager,0)` after fallback journal creation; despite check-in wording about the db file, the added call synchronizes the materialized rollback journal. Related [3.53 backport](https://sqlite.org/src/info/272d90d7f3), [3.50 backport](https://sqlite.org/src/info/5444d67e67), [3.44 backport](https://sqlite.org/src/info/feca97beee) explain the later maintenance context. The source tests whether ENABLE_BATCH_ATOMIC_WRITE is defined. Leaving it undefined, rather than setting it to zero, excludes this path. This is a narrow applicability finding, not assurance about every durability defect.

## Native lifetime and execution facts

| Area | Primary evidence / consequence |
| --- | --- |
| Open/prepare | [open](https://sqlite.org/c3ref/open.html) can return a nonnull handle on failure. Capture its diagnostics and close it. [prepare](https://sqlite.org/c3ref/prepare.html) compiles the first statement and returns a tail; v2/v3 retain SQL for reprepare. Success on a prefix does not validate the whole input. |
| Binding | [bind](https://sqlite.org/c3ref/bind_blob.html) copies TRANSIENT data before returning. STATIC data must survive reset until rebind/finalize. Destructor failure paths matter. Null pointers can mean NULL, so zero-length BLOBs need care. |
| Slots | The [parameter count](https://sqlite.org/c3ref/bind_parameter_count.html) is the maximum index. ?NNN creates gaps, and repeated names share indices. [names](https://sqlite.org/c3ref/bind_parameter_name.html) cannot distinguish all anonymous/gap cases. Unbound slots are NULL; never use this to fill omitted application arguments silently. |
| Columns | [accessors](https://sqlite.org/c3ref/column_blob.html) require the correct ROW state and column ordinal. Conversions, step, reset and finalize can invalidate pointers. Read the initial storage class before conversion. OOM can resemble NULL. Copy data before invalidation and check encoding, types and ranges. |
| Diagnostics | The [error APIs](https://sqlite.org/c3ref/errcode.html) expose messages and codes as mutable connection state. Later calls invalidate them; FULLMUTEX alone does not serialize the operation and diagnostic copy as a unit. MISUSE need not have valid diagnostics. Stock fields do not identify a guaranteed failing unique key; see [#40 research](0040-standard-sql-and-unique-errors.md). |
| Reset/finalize | [reset](https://sqlite.org/c3ref/reset.html) preserves bindings and can report a prior error or a new completion error, including RETURNING followed by BUSY. [finalize](https://sqlite.org/c3ref/finalize.html) destroys the statement even on error. Never retry the pointer. |
| Close | [close](https://sqlite.org/c3ref/close.html) leaves the connection alive on BUSY. close_v2 can create a zombie with deferred destruction, so OK does not prove that all children and resources have been destroyed. |
| Interrupt | [interrupt](https://sqlite.org/c3ref/interrupt.html) may run from another thread, but close must not race its use. A request can lose a completion race; an idle request does not latch for later work. Its effects can extend across running statements. Automatic DML rollback is context-specific, not a universal cancellation guarantee. |
| Callbacks | [progress](https://sqlite.org/c3ref/progress_handler.html) callbacks are approximate and can also run during preparation. SQLite can skip the non-reentrant [busy](https://sqlite.org/c3ref/busy_handler.html) callback. The [timeout](https://sqlite.org/c3ref/busy_timeout.html) counts sleeps, not the overall operation deadline. No hard abortion of arbitrary VFS work is guaranteed. |
| Threading | The [thread-mode](https://sqlite.org/threadsafe.html) and [threadsafe](https://sqlite.org/c3ref/threadsafe.html) documentation distinguishes compile-time, startup and connection settings. A compile-time setting of 0 cannot be escalated. Sequential calls can move threads, but shared mode does not protect complete copy/lifetime sequences. |

## Selected-source policy audit (3.54.1, not only historical 3.50.4)

Source references: [pragma.c](https://sqlite.org/src/file/src/pragma.c?ci=version-3.54.1), [auth.c](https://sqlite.org/src/file/src/auth.c?ci=version-3.54.1), [build.c](https://sqlite.org/src/file/src/build.c?ci=version-3.54.1), [vdbe.c](https://sqlite.org/src/file/src/vdbe.c?ci=version-3.54.1), [pager.c](https://sqlite.org/src/file/src/pager.c?ci=version-3.54.1), [pragma.h](https://sqlite.org/src/file/src/pragma.h?ci=version-3.54.1). APIs: [authorizer](https://sqlite.org/c3ref/set_authorizer.html), [actions](https://sqlite.org/c3ref/c_alter_table.html), [PRAGMAs](https://sqlite.org/pragma.html), [statement readonly](https://sqlite.org/c3ref/stmt_readonly.html).

- SQLite authorizes PRAGMAs before VFS dispatch and name lookup, including for unknown names. Schema resolution and explicit-temp opening can happen earlier. IGNORE does not reject every operation. Callback strings can be NULL or use arbitrary case.
- Argument presence does not classify a PRAGMA as a read or write. table_info(table) needs an argument, while checkpoint/optimize can have effects without arguments. query_only/foreign_keys/trusted_schema assignments mutate during prepare; EXPLAIN/readonly checking after prepare is not a barrier.
- The accepted built-in inspections do not intentionally assign settings/data but can load schema, resolve views/virtual tables, invoke xConnect, lock/recover or return filesystem paths. VFS PRAGMA interception comes first. Selected-source view-column derivation temporarily disables xAuth around result-column resolution; do not claim complete underlying ACL coverage.
- Selected PRAGMA table-valued forms prepare their direct PRAGMA in xFilter during outer evaluation. The authorizer must therefore stay installed through stepping. Hidden arguments differ. table_list has only a filter; object inspectors take object/schema; journal_mode/synchronous take only schema; the other listed observations have no hidden arguments.
- Authorization is not normally repeated on every cached step. Reprepare runs it again. Changing callback-owned policy data alone is not a cache invalidation protocol. Current query_only is checked at native write transaction start, including cached writes, but not a proof about every mutable policy.
- Semantic transaction/savepoint/ATTACH/DETACH actions can reject categories; they do not prevent implicit transactions, ON CONFLICT ROLLBACK or automatic rollback. ATTACH auth argument can be NULL for runtime filename expressions, not a generic evaluated path guard.
- PRAGMA busy_timeout changes busy handling; threads changes a sqlite3_limit; heap limits are library-global. Defensive/trusted-schema settings have narrower semantics and SQL counterparts, not a general configuration freeze or sandbox. Removing extension loading does not remove compiled-in modules.

## Values, transactions and platform boundaries

The [datatype](https://sqlite.org/datatype3.html), [floating-point](https://sqlite.org/floatingpoint.html) and [STRICT](https://sqlite.org/stricttables.html) documentation describes native INTEGER as i64 and REAL as binary64. SQLite has no Decimal or calendar storage classes. Affinity/casts/SQL may change values even with STRICT. NaN native bind becomes NULL in selected source; the product must reject it. Native getters alone are not checked conversion evidence.

SQLite provides [serializable isolation](https://sqlite.org/isolation.html) except when both shared cache and read_uncommitted permit dirty reads. WAL snapshots can fail promotion with BUSY_SNAPSHOT. [query_only](https://sqlite.org/pragma.html#pragma_query_only) is not a physically read-only/sandbox connection. [autocommit](https://sqlite.org/c3ref/get_autocommit.html) says whether an explicit transaction survived. It does not report commit history or establish the absence of unfinished implicit work. [txn_state](https://sqlite.org/c3ref/txn_state.html) supplies separate observations. Read these under exclusive access.

[Initialization](https://sqlite.org/c3ref/initialize.html)/[configuration](https://sqlite.org/c3ref/config.html) are library-global and lifecycle constrained. [Amalgamation](https://sqlite.org/amalgamation.html)/[compile options](https://sqlite.org/compile.html): internal static linkage does not hide every public API/global. [GNU loader hardening](https://sourceware.org/glibc/manual/latest/html_node/Dynamic-Linker-Hardening.html), [GCC visibility](https://gcc.gnu.org/onlinedocs/gcc/Code-Gen-Options.html), [ld](https://sourceware.org/binutils/docs/ld/Options.html), [objcopy](https://sourceware.org/binutils/docs/binutils/objcopy.html) show available techniques, not portable Rill isolation. Our one-host object audit is narrower than product build/link/loader evidence.

[Database mmap](https://sqlite.org/mmap.html) and selected [Unix VFS source](https://sqlite.org/src/file/src/os_unix.c?ci=version-3.54.1): MAX_MMAP_SIZE=0 removes database-file mapping, not WAL shared-memory mapping. [VFS](https://sqlite.org/vfs.html) controls files/locks/sync/random/time and sidecars beyond main path. [WASIp1](https://github.com/WebAssembly/WASI/blob/snapshot-01/phases/snapshot/docs.md) rights/locking/import limitations require a separate profile; [SQLite Wasm goals](https://sqlite.org/wasm/doc/trunk/about.md) are browser/JS-oriented, not WASI compatibility. No profile or import is approved by the existence of an old SQLITE_WASI source branch.

## Evidence actually executed versus not run

The [exact reference report](../../experiments/sqlite-provider/reference/results.md) records 98 native fixture checks plus integrity, prefix and hidden-object audits on one macOS arm64/Clang21 host. It found 276 prefixed globals and lower native limits of 2000 columns and 32766 parameters. Host SINGLETHREAD reconfiguration did not succeed (SQLITE_ERROR). Coexistence evidence covers only the basic dual-TU case. No archive, engine or binary was checked into the repo. The [protocol inventory](../../experiments/sqlite-provider/README.md) separately records Python model/header syntax checks.

No validation ran for the actual Rill compiler, driver, binding consumer, native leases, job queues, adoption or wake epochs. The investigation also ran no validation on other native cells or WASI, and no production migration, crash, fault, sanitizer, security or power-loss validation. All those gates remain unfulfilled. This note does not replace the human-confirmed contract with researcher choices or close #43/#30.
