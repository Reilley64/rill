# Native fixed-stack migration and retained native access

These executed standalone mechanism probes for #30 are not a complete Rill scheduler/checker or selection of a production Boost dependency. The source body and context-switch objects are compiled by LLVM/Clang **23.1.5** in O0/O2 for four binary targets. macOS/AArch64 runs natively; macOS/x86-64 uses Rosetta; Linux/AArch64 runs in the existing ARM64 VM; Linux/x86-64 is translated/emulated. Physical x86-64 hardware is not tested.

## Reproduce

```sh
python3 experiments/backend-30/native-lifecycle/run.py --out /tmp/rill-30-native-lifecycle
```

Requires the same LLVM 23/macOS SDK/Rosetta/existing Docker setup as the earlier #30 runner. `--cache` defaults to `/tmp/rill-30-lifecycle-tools`; `--llvm` can override the tool directory. The runner does not install system packages or modify existing containers/volumes. The runner downloads eight small pinned official assembly sources and verifies every SHA-256 before compiling. Linux C/C++/UAPI headers are copied from the immutable official Rust images into the temporary cache using newly created, never-started containers, then those containers are removed. Header symlink targets under `/usr/lib/linux` are copied too. LLVM IR is emitted and verifier-checked for each target/mode; retention checks require ordinary (`notail call`/`invoke`) terminal escape edges and disable sibling-call removal of the buffer-owning scope. That scope is not source-tail eligible while its loan/cleanup is outstanding. The separate proper-tail probes still use mandatory tails; these attributes apply only to this ordinary retention fixture. Containers for linking/execution have no network and are removed afterward.

The **Linux test body is also LLVM 23 output**, cross-compiled on macOS against those pinned headers. The images supply only GNU linking and the C++/pthread/libc runtime. The recorded dependency hashes identify every header used. No GCC-generated substitute test body is counted as LLVM output. `results.json` / `commands.json` retain source/tool/header hashes, immutable image digests, all commands and output. First-run header preparation adds commands relative to a warm-cache run. `evidence/` holds the recorded snapshots: **51 warm-cache commands / 80 observations**, four target binaries × O0/O2 × ten cases. Fresh header preparation adds commands. Assembly/object/executable/cache files remain outside the repository.

## Concrete cases

- **Parallel M:N control:** three fixed-stack contexts on two OS workers, two entering a shared atomic barrier before either can yield. The barrier requires genuinely overlapping execution, not merely sequential visits. All three contexts then resume on a different worker and dispose once. This is a small scheduling control, not a work-stealing/fairness/performance claim.
- **Normal completion:** a native pthread borrows a real address of an aligned automatic buffer on a mapped **1 MiB usable stack**. The context migrates at least 10,000 times between two persistent OS workers while the operation is pending. The actual job joins before the C++ scope returns. Its real C++ guard destructor then suspends on a required cleanup wait, migrates and remains masked despite a repeated cancellation request; it disposes once only after acknowledgement, and the mapping releases once afterward.
- **Cooperative cancellation/required join.** A real status handle requests cancellation, then is dropped. The guest enters a cleanup-pending/masked path but cannot dispose/reclaim while the native job still holds access. Actual job completion/join precedes guard disposal and unmapping. This demonstrates that explicit protocol, not every generated Rill cancellation state.
- **Recursive admission with a live native loan:** a small outside thunk checks actual SP against the generated body/entry/emergency footprint before each ordinary recursive body. Bodies contain real 8192-byte, 4096-aligned buffers and post-call work. An eight-edge success control completes nine bodies. A million-edge request then reaches the admission boundary and escapes terminally before another body prologue; both adjacent logical canaries remain intact. All recursive frames and the original loan scope remain suspended, and the native borrower accesses its buffer after guest failure before the backing can release. This composes pre-write checking with migration/retained access; it is not a recursive-fallback workaround.
- **Scoped child cleanup/join:** two real mapped contexts migrate while the child borrows the parent's automatic buffer. Parent exit enters a masked join. The child's destructor itself waits/yields, reads the parent's buffer on completion, and must finish before the parent can dispose or release storage. Handle drop and repeated cancellation do not end either required wait.
- **Exclusive native output:** while the owner is parked, the real native job mutates the borrowed stack buffer. Only after actual join does the migrated owner read the output/dispose; expected bytes are checked. There is no concurrent conflicting owner access.
- **Normal top-level exit with a background context:** the embedding marks the guest invocation ended while its background context remains parked. Only the native job's independent backing lease remains. It accesses the still-live buffer afterward; no guest global join or disposer is promised. Storage releases only after foreign access ends.
- **Fatal guest escape with work outstanding:** a `noreturn` guest termination helper jumps to the embedding scheduler **without returning or unwinding the owning C++ scope**. The terminated context is never resumed. Only the native job retains the backing; it reads the live buffer after guest termination, then releases the mapping. Guard disposal remains zero, as required by the absence of a fatal-cleanup guarantee.

- **Deep iterative cleanup and complete cause-like formatting:** 200,000 nodes include 133,333 actually constructed owning payloads and uninitialized payload slots. An explicit semantic worklist disposes constructed resources once in checked child-before-parent order. Actual non-inlined formatter/destructor callbacks suspend and migrate (180 callback yields), with their native local state live; cancellation remains pending during the masked traversal. All node identifiers are formatted without truncation and checked against an independent Python checksum; sampled native frame span stays bounded. This is mechanism evidence, not the Rill `Err<E>` representation or generated ownership checker.
- **Worklist allocation failure:** an injected native allocation failure takes a terminal `noreturn` guest escape before data allocation, with no recursive fallback or normal guest resumption. The earlier C control separately covers failure during worklist growth.

The top-level/fatal retention cases must not return from or unwind the buffer's scope and then read a dangling local. Keeping its old bytes mapped does not keep the local alive. Instead the scope stays suspended until backing release; its lifetime ends with storage release after the borrower stops. A raw context is discarded, not a high-level Boost fiber object whose destructor would force unwinding. Normal/cancel/output cases do finish the scope and run its real C++ guard, after the native job has joined.

A weak backing observer verifies that after guest termination there is exactly **one** remaining strong owner: the native job's lease. No observer secretly keeps the mapping alive. Native access-end, disposal and unmapping events are ordered. Completed status handles remain usable after the stack mapping is gone; they do not own execution storage. No allocation, saved activation or observer log accumulates per migration.

## Address and ABI profile

Each backing is one non-moving mmap with a **1 MiB logical usable region**, writable instrumentation pages immediately outside it, and protected physical pages beyond those. Sixty-four-byte canaries immediately below/above the logical region detect corruption without relying on a physical fault. Instrumentation/guards are not extra usable capacity. Guards and allocation metadata lie outside the 1 MiB usable region; fcontext register records and actual guest ABI frames consume that region. The automatic loan address is checked inside it and remains unchanged. The real native job has a **256 KiB / 4096-aligned automatic frame on its separate OS-thread stack**, verified disjoint from the managed region; that frame is initialized before migrations start and checked afterward. Native/thread-affine locks remain on that separate job stack, not on a migrating guest stack. A live floating accumulator is checked across migration too.

Use one context on at most one worker at a time; the scheduler's queues serialize ownership transfer and publish state through mutex/condition-variable synchronization. The native job accesses only its granted read-only/exclusive buffer and independent retention token. Workers start with the same round-to-nearest floating environment. No OS-thread-affine object, cached TLS pointer or OS-owned mutex guard lives across a guest yield. Source worker identity is copied from the explicit transfer packet, not inferred by a compiler-hoistable TLS lookup. Sanitizer fiber instrumentation, CET/shadow-stack profiles and arbitrary foreign reentry/environment changes are not tested here and need separate integration if enabled.

### Recursive footprint accounting

For each target/mode the runner emits `.su` data and audits the fixed-frame recursive entry/body plus the acyclic emergency helper graph. The runner rejects unknown/indirect emergency calls, recursive emergency helpers and non-static frames. The per-entry requirement sums their actual frame sizes plus **4240 extra bytes per node** (4096 alignment + 128 red-zone + 16 link allowance), a **16 KiB reserve** and **256 bytes** for the pinned assembly context save. It deliberately double-counts some storage. Source bodies have no dynamic alloca, OS/library call or unknown copy helper. Terminal-jump resumption and internal assertion/abort bug paths are not normal execution; the fixture forbids resuming terminated contexts.

Every recursive source body calls the outside entry for its child; live buffer reads after return prohibit TCO. The previous admission reserves entry/emergency space before the next entry can execute its own small prologue. Initial entry occurs on a fresh healthy 1 MiB context. Requirements are **41,656-67,216 bytes** for these profiles; these are fixture admission/headroom constants, not a new public minimum. Each failure has less remaining space than its requirement, intact adjacent canaries, no recursive body completion beyond the nine-body success control, and zero user disposers. Fatal reporting/checks occur on the external scheduler's OS stack, not the exhausted guest region. This is the permitted scheduler-termination mechanism, not a signal/altstack experiment.

The body/entry cycle is admitted per edge, not bounded by pretending the recursive call graph is acyclic. The separate capacity suite still supplies large outgoing argument/result and oversized-frame cases. No bound on every native runtime/library operation is claimed; unknown native work needs explicit separate-stack bridging or a separately admitted bound, not an unexplained call on a nearly exhausted managed stack.

These are actual native stack/loan/guard operations, but the guest stop/join/termination protocol is manually coded. The test does not prove automatic Rill ownership/eligibility checking, every provider's abortion contract, generated stack-clash protection or full ABI layouts. Deep traversal/worklist data is legitimate semantic data, not one hidden activation per eligible tail transfer. Native-capacity probes supply the separate large-copy/argument/result protection and ABI controls. The embedding explicitly waits for the native job to inspect the invariant; this is **not a language-level global exit join**.
